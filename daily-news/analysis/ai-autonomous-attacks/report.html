AIエージェントによる自律型攻撃は3年でどれだけ増えたか

日次セキュリティニュース要約 1,004ファイル・8,865記事項目を全文解析し、実際の攻撃者が実際の攻撃活動にAIを組み込んだ事例 73 件を抽出・手作業で分類した。研究・PoC とAIラボの事故は除外している。自律型の中核事例は 32 件。

スコープ

研究と事故を外し、攻撃活動への組み込みだけを数える

候補286件を本文確認のうえ3層に仕分けた。AIが被害者側にあるもの（プロンプトインジェクション脆弱性、AIサプライチェーン、偽AIツールのルアー）、防御側のAI利用、動向レポートに加えて、研究・PoC・レッドチーム（14件）とAIラボの評価中にモデルが範囲を逸脱した事故（12件）を除外している。

主な除外事例：GPT-4によるWebサイト自律ハッキング研究、PromptLock（学術PoC）、MalTerminal（実運用の観測なし）、マッキンゼーLilliへの自律攻撃エージェント検証、Unit 42のエージェント型ランサムウェア演習、Hugging Face侵害・RubyGems攻撃・独DSE Wiki乗っ取り・米加政府サイトへの侵入試行（いずれもAIラボ運用エージェントの逸脱）、CLOSEDQUORUM（犯罪者製だが実環境展開は未確認）。

カット1 ─ 時系列

月単位の増加：3年間ゼロ、2025年4月に初出、2026年Q3で爆発

「自律型の中核事例」は、AIエージェントが攻撃工程を自ら実行したもの（A1）と、マルウェア自体が実行時にLLMを呼んでコマンドやコードを動的生成するもの（A2）の合計。

  • 2023-06〜2025-03（22か月）はゼロ。AI支援型（B）は2024-02から出ているが、AIが攻撃を実行する事例は一件もない。2023-10〜2024-09の1年間を通じて自律型は0件。
  • 2025-04〜2026-06（15か月）で12件（0.8件/月）。AkiraBot（2025-04）を皮切りに、LameHug（LLM組込型マルウェアの初の公開文書化、2025-07）、HexStrike AIの実戦投入（2025-09）、GTG-1002（Claude Codeが工程の80〜90%を担う30組織標的の侵入、2025-11）と実環境の「初物」が並ぶ。
  • 2026-07以降の3か月で19件（6.3件/月）。7月5件 → 8月4件 → 9月10件。全32件の59%がこの3か月に集中している。
  • AI支援型（B）は2026年Q2でピークアウトし、Q3は自律型へ移っている。2026Q3のBは2件まで落ち、代わりにA1が16件。「AIで作った」から「AIが実行した」へ重心が移った。
  • 元データの記事数は3年で約1.1倍にしか増えていない。2023-10の273件に対し2026-09は309件。この増加は収集量の増加では説明できない。
カット2 ─ 攻撃者

攻撃者の内訳：自律型は金銭目的が過半、国家系はいまだ支援利用が中心

自律型の中核事例32件を攻撃者タイプで分けた。右端はAI支援型（B・人間主導）での件数で、自律型とは主役が入れ替わる。

  • 自律型の主役は金銭目的のサイバー犯罪で、コアの56%。ランサムウェア（JadePuffer 3件、GLOBAL GROUP、Claude Code悪用のRaaS）、カード情報スキミング（60万件超・100超サイト）、認証情報窃取キャンペーン（PaperCut脆弱性で395組織）、ビッシング基盤（ATHR、AnonyMousKIT）と、収益化手段が確立した領域に集中している。
  • 国家支援型は自律型では22%だが、AI支援型では19件で最多。国家系は「攻撃全体を自律化する」よりも「偵察・コード生成・文面作成・脆弱性調査をAIで加速する」使い方が依然として主流。ただしGTG-1002、SecFlow、Hermes／OpenClawマルチエージェント（アジア政府機関21システムを4日で侵害）、LameHug（APT28系）と自律化への移行も確認済み。
  • 帰属不明が2026年に0→7件へ急増。AIエージェントが攻撃主体になると、言語痕跡・TTP・インフラといった従来の帰属手がかりがモデル側に吸収される。DIVD侵害、Carbonato、スペインAEPDへの初報告、Sysdig観測のLLMエージェント侵入はいずれも攻撃者不明。
  • 2024年の自律型はゼロ。2024年に観測されたAI利用はすべて人間主導の支援利用で、その大半はOpenAI・Microsoftによる国家支援型アクターのアカウント停止報告だった。
カット3 ─ モデル／エージェント

使われたモデル：実行はClaude Code系、支援はOpenAI系、2026年に中国系とOSSが台頭

1事例が複数モデルを使う場合は重複計上。濃色が自律型コア、淡色がAI支援型を加えた分析対象全体。

  • 自律実行にはAnthropic系が最も多く使われている（コア6件）。Claude Code のようにターミナルでコマンドを実行できるコーディングエージェントが、そのまま攻撃オペレーターとして転用されている（GTG-1002、Claude Code＋DeepSeek-v4-proによる4カ国政府・金融標的、SecFlow、Anthropicが公表した約50組織標的のGTG-10007）。
  • OpenAI系は支援型で最多（9件）だが自律型では2件。攻撃者がマルウェア開発や文面生成に使う「汎用の相棒」としてはOpenAI系が最多である一方、実際に攻撃を実行させる段ではClaude Code・Gemini CLI・OSSエージェントが選ばれている。
  • 2026年に中国系モデル（DeepSeek 4件、Qwen 1件）とOSSエージェント（Hermes 4件、OpenClaw 1件）がゼロから立ち上がった。ガードレールの弱いモデルと自己ホスト可能なエージェントへのシフト。典型は「Hermes Agent を YOLO モード（無人承認）で動かし、推論は DeepSeek に投げる」構成（knaithe／KnYuan、タイ財務省、Carbonato）。
  • 役割分担型のマルチモデル構成が主流化している。SecFlow（Claude＝実行、Qwen・DeepSeek＝推論）、Claude Code＋DeepSeek-v4-pro（実行と脆弱性悪用の推論を分離）、s1ngularity（Claude Code・Gemini CLI・Amazon Q CLI を順に試行）。
  • 「悪性LLM」は分析対象に1件も入っていない。2023年に大きく報じられたWormGPT／FraudGPT系はツール供給に留まり、実際の攻撃活動への組み込みが報告された事例はない。自律型の実体は正規の商用モデル＋エージェント基盤である。
  • モデル非特定が自律型コアの12件（38%）で、うち11件が2026年。報告側がエージェントの挙動だけを観測し、背後のモデルを特定できていないケースが増えている（DIVD、スペインAEPD、Sysdig観測の侵入）。

手法と限界

この数字の読み方

出典はニュース要約であり、インシデントの母集団ではない。本統計は「報道・ベンダ公表された事例の数」で、実際の攻撃件数ではない。AIラボと大手ベンダの報告が多いという公表バイアスが乗っている。

「集計報告」9件は1行で複数の攻撃活動を含む。OpenAI・Googleのアカウント停止報告などは、1件が数十キャンペーンを代表している。個別事例だけで数えたい場合は granularity == "single"（64件、うち自律型コア31件）でフィルタすること。

A1とBの境界は報告の詳細度に依存する。「AIが80〜90%を担った」と明記されたGTG-1002はA1、「AIが被害環境内で自律動作した証拠はない」と明記されたSophos事例（2026-06-03）はB。自律性に言及しない報告は保守的にB側へ寄せた。

JadePufferは3件を別事例として数えている。同一の攻撃者による別キャンペーンという扱い。アクター単位で数えると1件になる。

2026-10は10/1〜10/7の6日分のみ。月次・四半期の最終点は未完了であり、グラフでは薄く示している。

抽出手順：全1,004ファイルを記事項目8,865件に分解（各ファイル定型の「ChatGPTの推奨事項」ブロックはノイズとして除去）→ AI関連語と攻撃関連語の共起で広域候補682件 → 攻撃者側がAIを手段として用いたパターンで283件 → 自律性キーワードによる漏れ確認で3件追加 → 286件すべて本文確認のうえ手作業でラベル付け → 研究・PoC、AIラボの事故、重複報道、実環境展開未確認を除外して73件を確定。
