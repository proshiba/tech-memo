#### WordPressバックアッププラグインの脆弱性、数百万サイトを乗っ取り攻撃にさらす
https://www.bleepingcomputer.com/news/security/wordpress-backup-plugin-flaw-exposes-millions-of-sites-to-takeover-attacks/

- 要約
    - WordPressの「All-in-One WP Migration and Backup」に、未認証攻撃者が最終的にRCEへ到達できる高深刻度のCVE-2026-19949が見つかった。
    - 脆弱性は7.109以前に存在するsecond-order SQL injectionで、trackback経由で埋め込んだデータが管理者のバックアップ復元時にSQLとして実行される。
    - 悪用によりai1wm_secret_keyを公開コメントへ漏えいさせ、そのキーを使って悪性.wpressアーカイブをインポートし、任意コード実行とサイト完全乗っ取りが可能となる。
    - 開発元のServMaskは8月20日にバージョン7.110で修正したが、記事時点で約35%しか更新されておらず、約325万サイトが脆弱なバージョンを使用している。
    - 攻撃成立には攻撃者が悪性trackback埋め込み後に、管理者がエクスポートとインポートを実行する必要があるが、同プラグインでは日常的な操作であるためリスクが残る。
- IOCの列挙
    - IOC情報なし
- 推奨事項
    - All-in-One WP Migration and Backupを修正版7.110以降へできるだけ早く更新する。
    - Wordfence Premium／Care／Response利用者は既に提供済みの防御ルールを有効にし、無料版利用者は更新を優先する。
- その他
    - CVE-2026-19949はPoCが検証され修正済みだが、記事内では実際の攻撃で悪用されているとの記載はない。
    - 一次ソース: https://www.wordfence.com/blog/2026/09/5-million-wordpress-sites-affected-by-sql-injection-vulnerability-in-all-in-one-wp-migration-and-backup-wordpress-plugin/
- ChatGPTの推奨事項
    - All-in-One WP Migration and Backup 7.109以前を使用している場合は、直ちに7.110以降へ更新してください。

#### Lenovoのメール検証不備を悪用しDropboxアカウントが侵害
https://www.bleepingcomputer.com/news/security/dropbox-accounts-breached-through-lenovo-email-verification-flaw/

- 要約
    - Dropboxは、Lenovo IDのメール検証プロセスの不備を悪用して、攻撃者が他人のメールアドレスで不正なLenovo IDを作成しDropboxへログインしたと警告した。
    - DropboxはLenovo Identity Provider Servicesを認証基盤の一部として利用しており、Lenovo側のメール所有確認を信頼したため既存Dropboxパスワードなしでアクセス可能だった。
    - 攻撃者による不正アクセスは8月4日から21日の間に発生し、Lenovoアカウントを持っていないDropbox利用者も影響を受けた。
    - DropboxとLenovoは問題を緩和し、Lenovo ID経由で認証された全セッションを失効させ、今後はLenovo ID利用時にもDropboxパスワード入力を必須にした。
    - 影響したDropbox利用者数は不明で、Lenovo側の調査ではLenovo顧客自体は今回の問題による影響を受けていないとされている。

- 推奨事項
    - 推奨事項なし
- その他
    - 攻撃者のグループ名、国籍、動機などの属性情報は記事内では不明。
    - 関連: https://x.com/yonilevy/status/2094521566826541248
- ChatGPTの推奨事項

#### Microsoft Defender、正規のGoogle検索リンクを悪意あるものとして誤検知
https://www.bleepingcomputer.com/news/security/microsoft-defender-flags-legitimate-google-search-links-as-malicious/

- 要約
    - Microsoftは、Defender for Office 365のSafe Linksが正規のGoogle検索URLを悪意あるものとして誤分類し、リンクのアクセスを遮断する問題を調査している。
    - 影響利用者には「Opening this website might not be safe」と警告が表示され、URLをコピーしてブラウザへ直接貼り付けても警告を回避できない。
    - Microsoft DefenderポータルやMicrosoft Sentinelでも、この誤検知に起因するアラートやインシデントが生成される可能性がある。
    - 原因は不正確なセキュリティ分類で、Microsoftは誤分類を修正して影響を解消する作業を進めている。
    - 影響地域や顧客数は公表されておらず、Microsoftは本件を限定的な範囲・影響を示す「advisory」として分類している。

    - 推奨事項なし
- その他
    - 一次ソース: http://admin.microsoft.com/#/MessageCenter/:/messages/MO1465962

#### 米国、8万人のフリーランサーをマルウェア感染させたロシア人を起訴
https://www.bleepingcomputer.com/news/security/us-charges-russian-for-infecting-80-000-freelancers-with-malware/

- 要約
    - 米司法省は、フリーランス雇用プラットフォームを悪用し約8万人へマルウェアを配布したとして、ロシア国籍のSearzhudin Tamirlanovich Aktulaevを起訴した。
    - Aktulaevは2016年6月～2017年11月、約255個の偽アカウントから悪性マクロを含むExcel添付ファイルを送信し、標的端末へマルウェアをダウンロードさせた。
    - 感染にはTVRAT（TeamSpy／TVSPY）とDarkVNCが使われ、TeamViewerやVNC Viewerを介して侵害端末を遠隔操作し、窃取データをC2へ送信した。
    - 攻撃者はECサイトのログイン資格情報や個人識別情報も窃取し、盗んだ情報を詐欺などの犯罪活動に利用したとされる。
    - Aktulaevは2025年5月にキプロスで逮捕され、2026年8月に米国へ身柄引き渡しされており、現在は連邦当局の拘束下にある。

#### Salityボットネットのインフラ、国際共同テイクダウンで解体
https://www.bleepingcomputer.com/news/security/sality-botnet-infrastructure-dismantled-in-joint-global-takedown/

- 要約
    - 米国、ブルガリア、ハンガリー、ルーマニアの当局と民間企業は、20年以上活動してきたP2P型Salityボットネットのインフラを共同作戦で解体した。
    - 米司法省、FBI、DCISは米国内のSality関連ドメインを差し押さえ、欧州当局も関連ドメインを押収し、P2P通信経路をシンクホール化した。
    - Salityは2003年頃から1万5,000台超へマルウェアを感染させ、認証情報窃取、スパム、プロキシ、ネットワーク悪用、DDoSなどに利用されてきた。
    - 最近も稼働していた2つのSalityネットワークは主にEggJaggerを配布し、クリップボード内の暗号資産ウォレットアドレスを攻撃者のものへ置換していた。
    - 既知のsuper peerをシンクホール化してペイロードやダウンロード指示の伝播を遮断し、感染端末のpeer listを消去することで攻撃者の制御から切り離した。

- 推奨事項
    - 推奨事項なし
- その他
    - CrowdStrikeは運営主体をSALTY SPIDERとして追跡しており、ロシアのバシコルトスタン共和国から活動している可能性が高いと評価している。
    - 一次ソース: https://www.justice.gov/usao-cdca/pr/sality-malware-disrupted-international-cyber-takedown
- ChatGPTの推奨事項

#### SonicWall、実際に悪用されているSMA1000のゼロデイ脆弱性を警告
https://www.bleepingcomputer.com/news/security/sonicwall-warns-of-actively-exploited-sma1000-zero-day-flaws/

- 要約
    - SonicWallは、SMA1000を対象とする2件の新たなゼロデイ脆弱性CVE-2026-83548とCVE-2026-83549が、RCE攻撃で連鎖悪用されていると警告した。
    - CVE-2026-83548はWorkPlaceインターフェースのSSRFに起因する最大深刻度のコマンドインジェクションで、任意コマンド実行につながる。
    - CVE-2026-83549はAppliance Management Consoleのコマンドインジェクションで、管理者権限を持つ攻撃者が任意のOSコマンドを実行できる。
    - 影響製品はSMA1000 6210、7210、8200vで、SonicWallファイアウォールのSSL-VPNやSMA 100シリーズは影響を受けない。
    - Shadowserverは400台超のSMA1000がインターネット公開中と追跡しており、SonicWallは最新ホットフィックスへの即時更新を強く求めている。
- IOCの列挙
    - IOC情報なし
- 推奨事項
    - 仮想・物理のSMA1000アプライアンスを最新のホットフィックス版へできるだけ早く更新する。
    - IOCが確認された場合はアプライアンスを再イメージし、全ユーザー・管理者パスワードを変更する。
    - IOCが確認された場合はTOTPトークンもリセットする。
- その他
    - CVE-2026-83548とCVE-2026-83549は既に実際の攻撃で連鎖悪用されており、SonicWall PSIRTがアクティブな悪用事例を確認している。
    - 攻撃者のグループ名、国籍、動機、具体的な侵害後活動は記事公開時点では不明。
    - 一次ソース: https://psirt.global.sonicwall.com/vuln-detail/SNWLID-2026-0016
- ChatGPTの推奨事項
    - SMA1000 6210／7210／8200vを運用している場合は直ちに最新ホットフィックスを適用し、侵害痕跡があれば再イメージと全認証情報・TOTPのリセットを実施してください。

#### 攻撃者、Faronics Deploy管理ツールを悪用してScreenConnectをインストール
https://www.bleepingcomputer.com/news/security/hackers-abuse-faronics-deploy-admin-tool-to-install-screenconnect/

- 要約
    - 攻撃者は正規のFaronics Deployエンドポイント管理基盤を悪用し、被害端末を攻撃者管理環境へ登録して遠隔管理権限を取得している。
    - 7月21日～8月20日に請求書、税務書類などを装うフィッシングが457台超へ到達し、正規署名済みFaronicsインストーラーの実行へ誘導した。
    - 登録後はFaronicsの正規配布機能からPowerShellを実行し、追加ツールを取得してConnectWise ScreenConnectを導入する。
    - ScreenConnectはFaronicsとは独立した第2の遠隔アクセス経路となり、Faronicsエージェントを削除されても攻撃者が対話型アクセスを維持できる。
    - Faronicsは8月5日の通知後に追加の悪用防止策を実施し、8月21日以降、Huntressが観測する悪用活動は大幅に減少した。
- IOCの列挙
    - IOC情報なし
- 推奨事項
    - C:\ProgramData\Faronics\Logs\ScriptRunner.logを確認し、遠隔実行されたスクリプト名や外部ダウンロードURLを調査する。
    - Faronics設定要求のckパラメータを確認し、同じ不正デプロイメントに登録された端末や悪意あるアカウントを特定する。
    - 通常使用していない端末にScreenConnectがインストールされていないか確認する。
- その他
    - 実際に観測されたフィッシング／遠隔アクセス攻撃であり、正規Faronics Deployを悪用したPowerShell実行とScreenConnect導入が確認されている。
    - 攻撃者のグループ名、国籍、動機などの属性情報は記事内では不明。
    - 一次ソース: https://www.huntress.com/blog/faronics-deploy-abuse
- ChatGPTの推奨事項
    - Faronics Deployを利用していない環境では予期しないFaronicsとScreenConnectの導入を直ちに全端末で確認し、該当端末を隔離してください。
